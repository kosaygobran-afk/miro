# MIRO 0.1.7

Source branch `0.1.7` merges into `main`. The package and lockfile are both version `0.1.7`.

## Changes

- Consolidated the storefront, customer and worker accounts, CEO/admin console, POS and overlays on the shared Light, Medium and Dark palette. Light uses warm white, Medium uses dove gray with pale panels, and Dark uses neutral near-black with charcoal panels. Gold actions use dark labels, reading accents remain legible, and semantic statuses retain distinct colors.
- Updated public and management surfaces, including commerce, POS, calculator, reporting and product controls, to use shared tokens instead of separate palette overrides. Appearance-specific geometry and the immutable historical Version 1 preset remain intact.
- Kept enhanced glass gated to Version 2, Dark mode and the shared setting. Updated theme documentation and regressions for shared colors, glass-off restoration, contrast and management/public parity.
- Refined product promotion badges and several management/public control surfaces as part of the shared palette pass.

## Verification

- `npm run lint` — passed.
- `npm run typecheck` — passed.
- `THEME_REVIEW=1 COMMERCE_PRODUCTION=1 python3 scripts/verify-commerce-integration.py` — passed. The isolated production build and browser fixture checked Services, Account and Admin in English and Hebrew across all three themes (18 combinations). Reading contrast measured at least 5.31:1; painted gold action contrast measured at least 9.31:1. The fixture used disposable synthetic actors and cleaned up afterward.
- `node --test --test-concurrency=2 tests/unit/*.test.mjs` — 497 of 499 passed. Two unchanged cache tests expect a 60-second cache value but receive 120 seconds: `tests/unit/public-presentation-loading.test.mjs` and `tests/unit/store-data-loading.test.mjs`. They are unrelated to this theme change and remain unresolved.

## Remaining owners and launch boundaries

- QA owns manual bilingual screen-reader and physical-device review. Automated contrast checks passed for the tested representative routes; they do not replace manual review of the full site.
- Business, legal and privacy approvals, pending migration rollout, monitoring/scheduler verification, payment readiness and official fiscal issuance remain governed by the existing handoffs. This release adds no schema changes, activates no payments, and is not evidence that production deployment or launch gates are complete.
- The two cache-TTL unit failures need engineering follow-up. No cache or storefront data behavior was changed in this release.
