# MIRO 0.1.1 — commerce, POS and storefront refinement

Release date: 2026-10-14. Source branch: `0.1.1`. Merge target: `main`.

The owner authorized including all accumulated source changes, pushing the next numbered release branch and merging it into `main`. The latest remote numbered branch was `0.1.0`; package and lockfile versions are now `0.1.1`. Next.js remains pinned to `16.3.8`.

## Release scope

- Integrated responsive POS catalog, cart, variants, customer/payment workspaces, scanner support, persisted floating register/calculator tools, fullscreen fallback, sales history and channel-aware reporting.
- Included the server commerce foundation: canonical money/VAT calculations, payment attempts/status/reconciliation/refunds, expense/reporting workspaces, protected internal document drafts/artifacts, business identity and provider configuration. Additive migrations, RLS/integrity/concurrency checks and C01–C18 implementation/readiness evidence accompany the source.
- Improved public presentation loading through limited cached configuration projections, parallel request-scoped catalog/auth reads, navigation settlement and reduced speculative catalog work. Added accessible display counters without changing canonical financial values.
- Refined product cards and shared grid/rail previews: separate image/details/pricing/action sections, contained media, larger separate thumbnail pickers, logical RTL arrows, keyboard gallery navigation, bounded scrolling details, stable footer hit-testing and 500ms touch/pen holds. Preserved all three themes, both locales, reduced motion and the protected Version 1 appearance path.
- Included the existing native NVIDIA CLI compatibility bridge/configuration and synthetic verification evidence. Native routing remains independent of Codex. Credentials, logs and private runtime backups remain outside Git.
- Included original PWA icons, licensed Hebrew PDF-preview fonts with source/license notices, operational documentation and historical verification evidence.

## Packaging and privacy

The local `main` had two unpublished commits after `origin/main`. One temporarily added a debug-session ZIP and the next removed it. The original local history is retained in `archive/local-main-before-0.1.1`, which is not pushed. The release is based on remote `main` and includes the complete resulting source tree in a new release commit, without introducing the deleted debug archive into remote history. No published history is rewritten.

Environment exports, private credentials, build/test outputs and generated Python caches are excluded. The root credential-bearing `preview` export remains ignored. Source credential-pattern and exact-local-secret scans print only findings metadata, never values. A final scan checks the staged blobs and commits actually being pushed.

## Verification

Release-time results are recorded in `docs/PROJECT_STATUS.md` and the pull request before merge. Checks cover lint, TypeScript, production build, repository formatting, unit tests, all migrations/SQL suites plus concurrency in disposable PostgreSQL, staged whitespace/credential checks and the previously recorded bilingual/theme/browser matrices. Local database verification never connects to the linked project. No live payment, stock mutation, official document issuance or new linked migration is part of release packaging.

The card refinement's final focused run passed 25 applicable Chromium/desktop-WebKit/iPhone-WebKit cases with one intentional touch-profile skip; its broader intermediate run and rerun limits are documented in `docs/product-card-widget-evidence-2026-10-14/verification.json`. Prior loading, POS, commerce and native-tooling evidence retains its original scope and date.

## Launch owners and limits

- Business/inventory/legal: approve commercial copy, catalog facts, media/manufacturer rights, selling prices, stock, identity and retention/terms.
- QA: complete bilingual physical-device, screen-reader, zoom and hardware acceptance. Automated checks do not replace manual approval.
- Provider/business: complete real signed merchant sandbox proof, gateway/bit readiness and merchant/PCI activation. Unknown external financial effects require reconciliation before retry. “ללא אובליגו” remains unavailable without an explicit approved provider contract.
- Accountant/business: verify fiscal identity, signing/allocation, output and retention before official issuance. Internal document drafts remain drafts; unavailable integrations cannot be enabled by an environment switch alone.
- Integration/operations: complete external notifications/webhooks and approved job/provider configuration. Existing enquiry/quote-only behavior remains available when payments/prices/stock are unapproved.
- Release/engineering: verify remote branch ancestry and merged state, then independently inspect Git-connected hosting checks. A successful Git merge does not certify a Ready deployment or activate financial/provider capabilities.

The release branch is retained after merge. Exact source/merge commits and remote verification belong in the pull request and final handoff so the recorded result is attached to immutable commits.
