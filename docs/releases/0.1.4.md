# MIRO 0.1.4 — brand identity, Dark surfaces and storefront cards

Release date: 2026-11-01; storefront follow-up: 2026-11-02. Source branch: `0.1.4`. Merge target: `main`.

This release packages the accumulated local changes after `0.1.3` and aligns the package and lockfile version with the release branch.

## Changes

- Introduces a shared, path-based MIRO Group Hebrew wordmark, accessible brand components, matching generated SVG, favicon and POS/PWA icons, and consistent branding across public, worker, management, POS and payment surfaces. `docs/BRANDING.md` describes the canonical artwork, regeneration and exact legacy campaign URL replacements.
- Refines enhanced Dark public, customer and worker surfaces to neutral black and gray while retaining gold accents, semantic colors, management exclusions and the existing appearance/glass gates. Media backplates remain neutral without recoloring product images.
- Updates bilingual labels, storefront campaign rendering, responsive alignment, design documentation and automated brand and surface checks. Existing saved design revisions, business identity and issued financial documents are not changed.

## Storefront follow-up — 2026-11-02

The owner requested all accumulated storefront changes on the latest existing release branch, `0.1.4`, followed by a merge and sync to `main`. The package version remains `0.1.4`; this is a follow-up on that branch.

- Version 2 grid, moving-rail and related-product cards share one renderer, with naturally contained photos, a continuous neutral media backplate, equal top badge and bottom page-entry bands, and a single gold border on all four sides during hover/focus. Source product photos remain unchanged.
- The bordered `Collection` / `קולקציה` label leads at the interface reading edge. Every assigned badge follows in an overflow loop at the shared product-rail speed, with one accessible copy, hover/focus/manual pause and reduced-motion/native-scroll fallbacks.
- Current prices sit above original prices and their adjacent discount percentages. Price/SKU, original-plus-discount/barcode and VAT/quantity share aligned rows in both locales. Only SKU, barcode and quantity appear in the sidebar; full specifications remain in the popup/product page. Popup brand values are centered, and long inline brand/model text retains full titles and popup values.
- All-products count/category filters and root navigation use compact horizontal chips. Grid/list controls change the actual layout. Load more reveals one batch after 200ms of fine-mouse hover, with cancellation and click deduplication; click, keyboard and touch activation remain available.
- Preview/hold exclusions, footer hit testing, Version 1, the management palette, all themes and truthful server-resolved prices/stock remain protected. Design, motion, category and agent handoffs describe the final behavior.

Final production verification passed **35/35 focused browser cases**, plus lint, typecheck, the optimized **150-route build**, scoped formatting and whitespace checks. Browser cases cover both locales, phone/desktop layouts, all themes, long price fixtures, actual code/price alignment, badge motion, hover-border pixels, popup content/focus and hover/click/keyboard/touch pagination. Earlier scoped accessibility scans and media-corner regressions retain their dated evidence in `docs/PROJECT_STATUS.md`; manual accessibility approval remains outstanding.

Known limitations: the pre-existing native phone-rail timing harness timeout remains separate from this visual/interaction suite. One external Fruugo product photo returns HTTP 403; the catalog owner should replace the blocked source with an approved stable upload. This release does not change catalog rows, owner settings, financial data or payment readiness.
